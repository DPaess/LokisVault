## What this is and why

Danilo plays Warframe through **GeForce Now** (cloud). Overlay tools such as AlecaFrame, WFInfo live mode or WFIT cannot read his inventory because the game does not run on his machine (and memory reading tools violate DE's terms anyway). He wants one place to:

1. Track the **relics** he owns (count per refinement: intact, exceptional, flawless, radiant).
2. Track the **prime parts** he owns.
3. Keep a **wishlist** of prime sets he wants to build, see which parts are missing, which of **his relics** drop them, and which **relics he should farm** (or buy) to get them.
4. Track **mastery**: every masterable item, prime and non prime, marked mastered or not, with remaining mastery points.
5. Decide which spare prime parts to **sell for platinum** and which to **trade for ducats** (Baro Ki'Teer), based on **warframe.market** prices.

All inventory is entered **by hand** in the site (Danilo is fine with that). Nothing ever touches the game. Inventory lives in the browser (`localStorage`) with JSON export/import for backup.

## Architecture

Static site on **GitHub Pages**, no backend, no server, no paid hosting.

```
public/                 # what Pages serves
  index.html            # shell: header, tabs, <main id="view">, datalists   (DONE)
  style.css             # dark theme, Orokin gold accent                      (DONE)
  favicon.svg           # abstract horned diamond, original art               (DONE)
  app.js                # all UI logic, vanilla JS ES module                  (DONE)
  data/items.json       # generated by scripts/build-data.mjs                 (DONE, committed)
  data/prices.json      # generated by scripts/fetch-prices.mjs               (DONE, committed)
scripts/
  build-data.mjs        # game data pipeline                                  (DONE, tested)
  fetch-prices.mjs      # warframe.market price pipeline                      (DONE, tested)
.github/workflows/      # daily refresh + Pages deploy                        (DONE)
README.md               # public readme                                       (DONE)
```

Why prices are fetched by a GitHub Action instead of the browser: warframe.market asks for at most 3 requests per second and may not send CORS headers, so the browser only reads `data/prices.json` that the Action writes once a day.

### Data sources

* `@wfcd/items` (npm, Warframe Community Developers): masterable items, prime sets, components, ducats. Note: in current versions the items only reference components by `uniqueName`. Full component records (name, `ducats`, `tradable`, `drops`) live in `data/json/Components.json`. The package `exports` field blocks `require('@wfcd/items/...')` subpaths, so the script reads files from `node_modules/@wfcd/items/data/json` by path.
* `https://raw.githubusercontent.com/WFCD/warframe-drop-data/main/data/relics.json`: every relic with rewards and chances per refinement (DE's official drop tables).
* `.../data/all.slim.json`: every mission/bounty drop. A relic counts as **farmable now** if `"<Era> <Name> Relic"` appears there. Prime Resurgence (Varzia, Aya) relics are not in drop tables, so they show as vaulted. Mention that in the UI.
* `https://api.warframe.market/v2`: `GET /items` (catalog with `slug`, `i18n.en.name`, `ducats`) and `GET /orders/item/{slug}/top` (top buy and sell orders, `data.buy[]` / `data.sell[]` with `platinum`, `rank`, `user.status`). Send headers `Language: en`, `Platform: pc`, `Crossplay: true`. Only orders whose user status is `ingame` or `online` count.

```jsonc
    { "id": "/Lotus/Powersuits/Loki/LokiPrime", "name": "Loki Prime", "category": "Warframe",
      "type": "Warframe", "prime": true, "xp": 6000, "mr": 0, "vaulted": true }

```

Current numbers: 809 masterable items, 162 prime sets, 594 prime parts, 801 relics (35 dropping now). Part names are exactly the relic reward names (e.g. `Wisp Prime Chassis Blueprint`), which is also how the game names them in the inventory. Some relic rewards are not prime parts (`Forma Blueprint`, `2X Forma Blueprint`, Requiem mods, Kuva, Riven Sliver, Exilus adapter, Ayatan star). Kavasa Prime collar parts are prime parts with `sets: []`.

Mastery categories in the data: Warframe, Primary, Secondary, Melee, Archwing (incl. arch guns/melee), Companion (sentinels, pets, companion weapons), Modular (Zaw strikes, Kitgun chambers, K-drive decks), Necramech. Known gaps: Amps, MOA/Hound parts beyond what @wfcd lists, Plexus, intrinsics and star chart are not included. Fine for v1, mention it in the README.

Mastery points: 200 per rank for frames, companions, archwings, necramechs, K-drives, 100 per rank for weapons. Rank cap 30 (40 for Kuva/Tenet/Coda style weapons and necramechs, taken from `maxLevelCap`).

### `public/data/prices.json` shape (produced by fetch-prices.mjs)

```jsonc
{ "generatedAt": "ISO date or null", "source": "...",
  "prices": {
    "Loki Prime Chassis Blueprint": { "slug": "...", "sell": 5, "sellMed": 6, "buy": 4, "sellers": 5, "ducats": 45 },
    "Loki Prime Set": { ... },
    "Neo H4 Relic": { ... }
  } }
```

Keys are our names, plus ` Set` for sets and ` Relic` for relics (intact price). `sell` is the cheapest live seller, `sellMed` the median of the five cheapest live sellers (use this as "the price"), `buy` the best live buy order. Entries can carry `stale: true` when a fetch failed and the previous value was kept.

**fetch-prices.mjs is tested** against the real v2 API. Names match almost one to one (1555 of 1557, the two misses are relics the market does not list). Relic orders carry a `subtype` (refinement), only `intact` orders are priced. `/orders/item/{slug}/top` returns at most five orders per side. A full run takes about 10 minutes.

### State (localStorage key `lokisvault:v1`)

```js
{
  v: 1,
  relics:   { "Neo H4": { intact: 2, exceptional: 0, flawless: 0, radiant: 1 } },
  parts:    { "Loki Prime Chassis Blueprint": 1 },
  wishlist: ["Loki Prime"],                 // set names
  mastered: { "/Lotus/Powersuits/Loki/LokiPrime": true },   // keyed by mastery id
  settings: { ducatRatio: 10 }               // ducats per plat threshold
}
```

Drop zero counts from storage. Wrap every localStorage access in try/catch.

Helper: `priceOf(name)` returns `prices[name]?.sellMed ?? prices[name]?.sell ?? null`. Sets use `"<set> Set"`, relics `"<relic> Relic"`.

Derived "need" for a part = sum over wishlist sets of `part.count`. "Missing" = need minus owned (min 0). "Spare" = owned minus need (min 0). Parts of wishlist sets are **wanted**.

### Tabs

1. **Overview**: stat tiles for mastery progress (points and items, with `.bar`), wishlist sets completed vs total and missing part count, relics owned (total count, how many contain wanted parts), spare parts total value in plat (sum of `priceOf × spare`) and in ducats. A short "next steps" list: top 5 owned relics by number of wanted parts, and wanted parts you have no relic for.
2. **Relics**: input with `list="dl-relics"` plus Add button. One `.card` per owned relic: name, era, badge "Dropping now" (`.farm`) or "Vaulted" (`.vault`), four number inputs for the refinements, rewards list colored by rarity showing chance for the best refinement owned and the price (`p`) and ducats, rewards needed for the wishlist highlighted with `.want`. Show expected value per opening (sum of chance × price) for intact and radiant, plat and ducats. Toolbar: filter (all, has wanted parts, vaulted only), sort (EV, name, count). Remove button on each card.
3. **Prime parts**: input with `list="dl-parts"` and quantity, Add. Table of owned parts: name, set(s), owned (editable number), needed for wishlist, ducats, price. Group or sort by set. Show sets you can build right now from owned parts.
4. **Wishlist**: input with `list="dl-sets"`, Add. One card per set: completion bar, set market price, each part as a `.part-line` with have/need and, when missing, where to get it:
   * "In your relics:" owned relics that contain it with counts and chance for the owned refinement.
   * "Farm:" relics that contain it and are `farmable`, sorted by chance.
   * if every relic is vaulted: "Vaulted. Buy on warframe.market for ~Xp" (link to `https://warframe.market/items/<slug>` when the slug is known) and mention Prime Resurgence.
   Mark set as built: removes it from the wishlist and marks its mastery item as mastered.
5. **Mastery**: summary bar (mastered points / total, items). Filters: search, category, prime or non prime, status (default: not mastered). Table with checkbox, name, category, type, xp, MR requirement, badge for prime vaulted. For an unmastered prime that is not in the wishlist, an "Add to wishlist" button. Bulk actions: "Mark all shown as mastered" and "Unmark all shown", both with `confirm()`. This bulk action is how Danilo will do the first fill quickly.
6. **Sell or ducat**: every part with spare > 0. Columns: part, spare, price (sellMed), best buy, ducats, ducats per plat, verdict, value of the spare stack. Verdict: no price data → "Hold" (`.hold`). `ducats / price >= settings.ducatRatio` → "Ducats" (`.ducat`), otherwise "Sell" (`.sell`). The ratio is editable at the top (default 10, explain it in one line). Totals at the bottom for the sell pile in plat and the ducat pile in ducats. Also list full spare sets where selling the set beats selling parts separately.
7. **Data**: export JSON (download `lokisvault-backup-YYYY-MM-DD.json`), import JSON file (validate, replace state), reset (confirm). **Bulk paste** textarea with mode select (relics and parts / mastered items):
   * relics: lines like `Neo H4`, `2 Neo H4 Radiant`, `Neo H4 Relic (Radiant) x3`, `3x lith g1`.
   * parts: `Loki Prime Chassis`, `2x Loki Prime Chassis Blueprint`, `Ash Prime Systems x2`. Match case insensitively, accept a missing trailing "Blueprint", accept a unique prefix match.
   * mastered: one item name per line.
   Adds to the existing counts and shows a report of matched lines and unmatched ones.

Show a small `.toast` after saves and imports. Everything must work at phone width.
